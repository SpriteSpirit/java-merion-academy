## Наследование в Java

- механизм, при котором один класс (подкласс) может наследовать/перенимать поля другого класса
- класс, от которого происходит наследование, называется родительским или супер классом
- для наследования используется ключевое слово `extends`
- нет поддержки множественного наследования классов, но можно реализовать несколько интерфейсов

### Конструкторы и наследование

- конструкторы не наследуются в отличие от методов, но можно вызвать конструктор родителя через
  `super()`
- если в родителе нет конструктора без аргументов, то в дочернем классе обязательно нужно явно
  вызвать подходящий родительский конструктор

```java
class Animal {

    Animal(String name) {
    }
}

class Dog extends Animal {

    Dog(String name) {
        super(name); // иначе будет ошибка
    }
}
```

### Переопределение методов

- дочерний класс может переопределить родительский метод
- для переопределения используется аннотация `@Override` - защитит от ошибок, если сигнатура метода
  не совпадает (Какой метод вызовется — решается во время выполнения (runtime, динамический
  полиморфизм))
- переопределение подчиняется правилам:
    - модификатор доступа `не может` быть более строгим (может быть более доступным)
        - чтобы не сломать полиморфизм: код, который работал с родителем, должен работать и с
          потомком
            ```java
            class Animal {
                protected void makeSound() { }
            }
            
            class Dog extends Animal {
                @Override
                public void makeSound() { } // ✅ можно: сделал более доступным
            }
            
            class Cat extends Animal {
                @Override
                private void makeSound() { } // ❌ нельзя: сделал менее доступным
            }
            ```
    - тип возвращаемого значения может быть ковариантным (вернуть более конкретный тип)
    ```java
    class Animal { }
    
    class Dog extends Animal { }
    
    class AnimalFactory {
        Animal create() {
            return new Animal();
        }
    }
    
    class DogFactory extends AnimalFactory {
        @Override
        Dog create() { // ✅ можно вернуть более конкретный тип
            return new Dog();
        }
    }
    ```
  #### ⚠️ Но нельзя «расширять» тип:
    ```java
    class CatFactory extends AnimalFactory {
        @Override
        Object create() { // ❌ ошибка: Object шире, чем Animal
            return new Object();
        }
    }
    ```
    - можно бросать только те же исключения или более конкретные
        - Метод-потомок может бросать:
            - те же исключения, что родитель,
            - или более «узкие» (подклассы исключений).
            - но не более «широкие».

    ```java
        class Animal {
    
        void eat() throws Exception {
        }
    }
    
    class Dog extends Animal {
    
        @Override
        void eat() throws IOException {
        } // ✅ IOException — наследник Exception
    }
    
    class Cat extends Animal {
    
        @Override
        void eat() throws Throwable {
        } // ❌ Throwable шире, чем Exception
    }
    ``` 
  ### Что такое динамическая диспетчеризация (dynamic method dispatch)
    - Это механизм, при котором выбор, какой метод вызвать, происходит во время выполнения (
      runtime), а не во время компиляции.
    - То есть тип объекта, а не тип ссылки, решает, какая реализация метода будет выполнена.
    - Динамическая диспетчеризация — это техническое объяснение полиморфизма:
        - Методы вызываются по типу объекта, а не по типу ссылки
    - Поля и static методы не участвуют в динамической диспетчеризации.

```
Тип переменной      → определяет, что компилятор разрешает вызвать
Тип объекта         → определяет, какой метод реально выполнится (runtime)

          Animal a
             │
    ┌────────┴─────────┐
  new Dog()           new Cat()
    │                   │
  makeSound()          makeSound()
    │                   │
   Bark                 Meow
```

#### Отличие от полей и static методов

| Элемент            | Выбор на этапе компиляции | Выбор на этапе выполнения           |
|--------------------|---------------------------|-------------------------------------|
| Методы (не static) | ❌ Нет                     | ✅ Да (динамическая диспетчеризация) |
| Поля               | ✅ Да                      | ❌ Нет                               |
| static методы      | ✅ Да                      | ❌ Нет                               |

#### Ключевые моменты

1. Методы: динамический выбор → runtime
2. Поля: выбор по типу переменной → compile-time
3. static методы: выбор по типу переменной → compile-time
4. @Override помогает проверять корректность подписи метода при реализации интерфейсов или
   переопределении методов родителя

#### ИТОГ:

- Доступность: можно расширять доступ (protected → public), но не сужать.
- Возвращаемый тип: можно оставить тот же или указать более конкретный (ковариантный).
- Исключения: можно бросать такие же или более узкие, но не более широкие.

### Поля и наследование

- поля не переопределяются, а скрываются (решается во время компиляции по типу ссылки).
    - если в родителе есть поле `int x` и в дочернем классе `int x`, то у каждого свой `int x`
    - при доступе через ссылку типа родителя будет использовано родительское поле
    - какое поле использовать — определяется по типу ссылки, а не по объекту.
      ```java
      Animal a = new Dog(); // ссылка типа Animal, объект типа Dog
      Dog d = new Dog();    // ссылка типа Dog, объект типа Dog
      
      Animal a = new Dog();
      Dog d = new Dog();
      
      System.out.println(a.type); // 👉 "Animal"
      System.out.println(d.type); // 👉 "Dog"
      ```

      #### ИТОГ:
        - Методы живые — подстраиваются под объект.
        - Поля мёртвые — жёстко привязаны к типу переменной.

### Модификаторы доступа

- private - доступ только в текущем классе
- default (package-private) - доступ в пределах пакета
- protected - доступ в пределах пакета + наследники
- public - доступ везде

#### Разница между protected vs package-private

📍 package-private (default)

```java
class Animal {

    void sleep() {
    } // нет модификатора → package-private
}
```

- Метод доступен только классам в том же пакете.
- Классы вне пакета (даже наследники) не увидят этот метод.

📍 protected

```java
class Animal {

    protected void eat() {
    }
}
```

- Метод доступен:
    - всем классам в том же пакете,
    - наследникам из других пакетов.

```java
// package animals
public class Animal {

    protected void eat() {
    }

    void sleep() {
    } // package-private
}

// package pets
public class Dog extends Animal {

    void test() {
        eat();   // ✅ можно (наследник, даже из другого пакета)
        sleep(); // ❌ нельзя (package-private доступен только в пакете animals)
    }
}
```

#### Итог:

- `protected` открывает доступ наследникам вне пакета, а `default` — нет.

| Модификатор | Доступ внутри класса | Доступ в пакете | Доступ для наследников       | Доступ везде |
|-------------|----------------------|-----------------|------------------------------|--------------|
| `private`   | ✅ Да                 | ❌ Нет           | ❌ Нет                        | ❌ Нет        |
| `default`   | ✅ Да                 | ✅ Да            | ❌ Нет                        | ❌ Нет        |
| `protected` | ✅ Да                 | ✅ Да            | ✅ Да (даже в других пакетах) | ❌ Нет        |
| `public`    | ✅ Да                 | ✅ Да            | ✅ Да                         | ✅ Да         |

#### Примеры

```java
// package animals
public class Animal {

    private String secret;     // только в этом классе
    String name;               // package-private, доступ в пакете

    protected void eat() {
    }   // доступ в пакете + наследникам

    public void sleep() {
    }    // доступ везде
}
```

#### Советы

- `private` → для инкапсуляции полей.
- `default` → удобно для «внутрипакетного» API.
- `protected` → если класс планируется расширять наследниками из других пакетов.
- `public` → для полного внешнего доступа.

### Final и наследование

- `final class` - нельзя наследовать
- `final method` - нельзя переопределить
- `final` переменные/поля - нельзя переназначить (но можно менять содержимое объекта, если это не
  immutable)

#### Когда класс помечен как `final`, это может иметь смысл в следующих случаях:

- Безопасность:
    - сохранение интегритета класса и защита от модификаций через наследование.
- Эффективность:
    - компилятор оптимизирует код для `final` классов, так как он знает, что нет подклассов, которые
      могут изменить его поведение.
- Проектирование API:
    - при разработке библиотеки или фреймворка для гарантии того, что класс не будет нарушен или
      изменен в будущем.

#### Для примитивов всё просто: значение закреплено навсегда.

```java
final int x = 10;
x =20; // ❌ ошибка: final переменную нельзя переназначить
```

#### Ссылки на объекты

```java
final StringBuilder sb = new StringBuilder("Hello");
sb.

append(" World");  // ✅ можно менять содержимое объекта
System.out.

println(sb); // "Hello World"

sb =new

StringBuilder("Test"); // ❌ ошибка: нельзя переназначить ссылку
```

`final` защищает ссылку (куда указывает переменная), но не сам объект в куче.

#### Immutable объекты

```java
final String text = "Hello";
text.

toUpperCase(); // создаёт новый объект, но `text` остаётся прежним
```

`String` — `immutable`, значит его содержимое изменить нельзя вообще.
Даже без `final`.
Если к `String` добавить `final`, то нельзя будет ссылку поменять.

#### Когда можно менять ссылку?

- Если переменная обычная (не `final`) → ссылку можно менять сколько угодно:

```java
String text = "Hello";
text ="World";   // ✅ ссылка изменилась
text ="Java";    // ✅ снова изменилась
```

#### Когда можно менять ссылку?

- Если переменная объявлена с final → ссылку переназначить нельзя:

```java
final String text = "Hello";
text ="World"; // ❌ ошибка: нельзя переприсвоить final переменную
```

Но! Даже с `final` объект остаётся тем же. Если он `mutable` — содержимое менять можно:

```java
final StringBuilder sb = new StringBuilder("Hi");
sb.

append(" there"); // ✅ меняем объект
// sb = new StringBuilder("Test"); // ❌ нельзя переназначить ссылку
```

#### А что со String?

`String` — immutable, то есть сам объект менять нельзя вообще.

```java
String s = "Hello";
s.

toUpperCase(); // создаётся новый объект "HELLO", но старый "Hello" не меняется
```

Если переменная не `final` → мы можем переназначить ссылку на новый объект:

```java
String s = "Hello";
s =s.

toUpperCase(); // ✅ теперь s указывает на новый объект "HELLO"
```

Если переменная `final` → переприсвоить нельзя:

```java
final String s = "Hello";
s =s.

toUpperCase(); // ❌ ошибка: ссылка s «застыла» на "Hello"
```

> #### Итог
> - Менять ссылку = переприсваивать переменную, чтобы она указывала на другой объект.
> - Без `final` → можно менять ссылку.
> - С `final` → ссылка фиксируется навсегда.
> - `Mutable` объект (`ArrayList`, `StringBuilder`) → содержимое менять можно, но не ссылку.
> - `Immutable` объект (`String`) → содержимое менять нельзя, а если `final` — то и ссылку нельзя
    переприсвоить.

#### `final` + mutable/immutable + ссылка

| Тип переменной                 | Что делает `final`?                     | Можно менять ссылку? | Можно менять содержимое объекта?       | Пример                                                                   |
|--------------------------------|-----------------------------------------|----------------------|----------------------------------------|--------------------------------------------------------------------------|
| **Примитив (int, double …)**   | Значение «замораживается»               | ❌ Нет                | ❌ Нет (значение фиксировано)           | `final int x = 5; x = 10; // ошибка`                                     |
| **Ссылка на mutable объект**   | Ссылка фиксируется, объект живой        | ❌ Нет                | ✅ Да (объект можно изменять)           | `final List<String> l = new ArrayList<>(); l.add("Hi"); // ок`           |
| **Ссылка на immutable объект** | Ссылка фиксируется, объект неизменяемый | ❌ Нет                | ❌ Нет (объект нельзя менять)           | `final String s = "Hi"; s.toUpperCase(); // новый объект, s не меняется` |
| **Обычная ссылка (без final)** | Ссылка свободно меняется                | ✅ Да                 | Зависит от объекта (mutable/immutable) | `String t = "A"; t = "B"; // ссылка поменялась`                          |

---

#### Запомнить просто

- `final` → **ссылка приклеена**.
- mutable объект → **внутри можно копаться**.
- immutable объект → **внутри трогать нельзя**.

#### Примитивы

```java
public class FinalPrimitives {

    public static void main(String[] args) {
        final int x = 10;
        // x = 20; // ❌ ошибка компиляции: нельзя переназначить final переменную

        System.out.println(x); // ✅ вывод: 10
    }
}
```

#### Ссылка на mutable объект

```java
import java.util.ArrayList;
import java.util.List;

public class FinalMutable {

    public static void main(String[] args) {
        final List<String> list = new ArrayList<>();

        list.add("Hello");     // ✅ можно менять содержимое
        list.add("World");

        // list = new ArrayList<>(); // ❌ ошибка: нельзя переназначить ссылку

        System.out.println(list); // ✅ вывод: [Hello, World]
    }
}
```

#### Ссылка на immutable объект (String)

```java
public class FinalImmutable {

    public static void main(String[] args) {
        final String text = "Hello";

        String upper = text.toUpperCase(); // создаётся НОВЫЙ объект "HELLO"
        System.out.println(text);  // ✅ вывод: Hello (старый не изменился)
        System.out.println(upper); // ✅ вывод: HELLO

        // text = "World"; // ❌ ошибка: нельзя переназначить ссылку
    }
}
```

#### Обычная ссылка (без final)

```java
public class NotFinal {

    public static void main(String[] args) {
        String text = "Hello";

        text = "World"; // ✅ ссылка поменялась
        System.out.println(text); // вывод: World
    }
}
```

#### Запомнить логику можно так:

- `final` = «ссылку прибили гвоздями» 🪛
- `mutable` объект = «коробка открыта, можно менять содержимое» 📦
- `immutable` объект = «коробка запаяна, внутри ничего не поменять» 🔒

### Абстрактные классы

- ключевое слово `abstract`:
    - может содержать как абстрактные методы (без реализации), так и обычные
    - нельзя создать экземпляр
    - подкласс обязан реализовать все абстрактные методы, если он сам не абстрактный
- отличие от интерфейса:
    - абстрактный класс может иметь состояние (поля)
    - класс может наследовать только один абстрактный класс, но несколько интерфейсов

#### Абстрактный класс с абстрактным методом

```java
abstract class Animal {

    String name;

    Animal(String name) {
        this.name = name;
    }

    // Абстрактный метод — без реализации
    abstract void makeSound();

    // Обычный метод
    void sleep() {
        System.out.println(name + " is sleeping...");
    }
}

class Dog extends Animal {

    Dog(String name) {
        super(name);
    }

    // Обязаны реализовать makeSound(), иначе ошибка
    @Override
    void makeSound() {
        System.out.println(name + " says: Woof!");
    }
}

public class Main {

    public static void main(String[] args) {
        // Animal a = new Animal("Generic"); // ❌ нельзя создать абстрактный класс
        Dog d = new Dog("Buddy");
        d.makeSound(); // ✅ Buddy says: Woof!
        d.sleep();     // ✅ Buddy is sleeping...
    }
}
```

#### Отличие от интерфейса

```java
// Интерфейс: только методы (до Java 8 — без реализации)

// Абстрактный класс: может хранить состояние (поля)
abstract class Bird {

    String name;

    Bird(String name) {
        this.name = name;
    }

    abstract void sing();
}

// Конкретный класс может наследовать абстрактный класс И имплементировать интерфейс
class Sparrow extends Bird implements Flyable {

    Sparrow(String name) {
        super(name);
    }

    @Override
    void sing() {
        System.out.println(name + " sings chirp-chirp!");
    }

    // переопределяем метод интерфейса
    @Override
    public void fly() {
        System.out.println(name + " is flying!");
    }
}

public class Main2 {

    public static void main(String[] args) {
        Sparrow s = new Sparrow("Jack");
        s.sing(); // ✅ Jack sings chirp-chirp!
        s.fly();  // ✅ Jack is flying!
    }
}
```

### Интерфейсы и наследование

- в Java 8+ интерфейсы могут иметь default, static и private методы с реализацией.
- интерфейсы могут наследовать другие интерфейсы.
- множественное наследование интерфейсов разрешено.

### Полиморфизм

- переменная хранит ссылку на объект, и тип переменной определяет доступные методы во время
  компиляции
- тип объекта определяет какой метод будет вызван во время выполнения

```java
Animal a = new Dog();
a.

makeSound(); // вызовет реализацию Dog
```

#### Суть полиморфизма

1. Тип переменной → что можно вызвать
    - Компилятор проверяет: «А есть ли у этого типа такой метод?»
2. Тип объекта → какая реализация метода реально выполнится
    - Во время выполнения `JVM` смотрит на реальный объект и вызывает соответствующую версию метода.

```java
class Animal {

    void makeSound() {
        System.out.println("Some sound");
    }
}

class Dog extends Animal {

    @Override
    void makeSound() {
        System.out.println("Bark");
    }
}

public class Main {

    public static void main(String[] args) {
        Animal animal = new Dog(); // ссылка типа Animal, объект типа Dog

        a.makeSound(); // ✅ Bark
    }
}
```

#### Разбор:

- Компилятор смотрит на `animal` → это `Animal` → проверяет: есть ли метод `makeSound()` у `Animal`?
  Есть ✅ → компиляция успешна.
- `JVM` во время выполнения смотрит на реальный объект → это `Dog` → вызывается метод
  `Dog.makeSound()`.

#### Мнемоника:

- Тип переменной = «что можно вызвать» (компилятор).
- Тип объекта = «что реально произойдёт» (runtime).

# Полиморфизм в Java (динамический)

| Тип переменной | Тип объекта | Вызов метода `makeSound()` | Что реально выполняется   |
|----------------|-------------|----------------------------|---------------------------|
| Animal         | Animal      | a.makeSound()              | Animal.makeSound()        |
| Animal         | Dog         | a.makeSound()              | Dog.makeSound()           |
| Animal         | Cat         | a.makeSound()              | Cat.makeSound()           |
| Dog            | Dog         | d.makeSound()              | Dog.makeSound()           |
| Cat            | Cat         | c.makeSound()              | Cat.makeSound()           |
| Dog            | Animal      | ❌ невозможно               | ❌ компилятор не пропустит |

#### Пояснения

- Тип переменной → компилятор смотрит, что разрешено вызвать.
- Тип объекта → JVM решает, какая реализация метода реально будет выполнена.
- Если метод есть только в потомке, но переменная типа родителя → компилятор не даст вызвать.

# Поля vs Методы в наследовании (Java)

| Тип переменной | Тип объекта | Доступ к полю `name` | Вызов метода `makeSound()` |
|----------------|-------------|----------------------|----------------------------|
| Animal         | Animal      | a.name → Animal.name | a.makeSound() → Animal     |
| Animal         | Dog         | a.name → Animal.name | a.makeSound() → Dog        |
| Dog            | Dog         | d.name → Dog.name    | d.makeSound() → Dog        |
| Animal         | Cat         | a.name → Animal.name | a.makeSound() → Cat        |
| Cat            | Cat         | c.name → Cat.name    | c.makeSound() → Cat        |

#### Пояснения

- Поля (fields) выбираются по типу переменной → статически, во время компиляции.
    - Даже если объект на самом деле потомок, поле родителя «скроет» поле потомка при доступе через
      родительскую ссылку.
- Методы выбираются по типу объекта → динамически, во время выполнения (runtime).
    - Это и есть динамический полиморфизм.

### Методы vs поля

> Почему методы переопределяются, а поля нет

- `Методы`: переопределяются, т.к. вызываются по типу объекта (динамический полиморфизм).
- `Поля`: не переопределяются, т.к. выбираются по типу ссылки (статически).

```java
class Animal {

    String name = "Animal";

    void sound() {
        System.out.println("Animal");
    }
}

class Dog extends Animal {

    String name = "Dog";

    void sound() {
        System.out.println("Bark");
    }
}

Animal a = new Dog();
System.out.

println(a.name); // Animal
a.

sound();                  // Bark
```

### Конструктор родителя

> Когда обязательно писать super(...)

- `super(...)` нужно использовать, когда конструктор родителя не имеет конструктора без параметров.
- Если родительский конструктор пустой, вызов super() вставляется автоматически.

```java
class Animal {

    Animal(String name) {
    }
}

class Dog extends Animal {

    Dog() {
        super("Buddy"); // обязательно, иначе ошибка
    }
}
```

### Приведение типов и ClassCastException

> Приведение объекта к неправильному типу вызывает ClassCastException во время выполнения:

```java
Animal a = new Animal();
Dog d = (Dog) a; // ❌ runtime exception
```

> Правильное приведение работает, когда объект реально принадлежит потомку:

```java
Animal a = new Dog();
Dog d = (Dog) a; // ✅ ок
```

### Методы static

> `static` методы не переопределяются, а скрываются (`method hiding`).
>
> Выбор метода происходит по типу переменной, а не объекта.

```java
class Animal {

    static void info() {
        System.out.println("Animal");
    }
}

class Dog extends Animal {

    static void info() {
        System.out.println("Dog");
    }
}

Animal a = new Dog();
a.

info(); // Animal (по типу ссылки)
```

### Object — родитель всех классов

Все классы наследуют `Object`.

```text
Методы:
`equals()` → проверка равенства объектов
`hashCode()` → для работы в коллекциях
`toString()` → строковое представление
`clone()` → копирование объектов
```
