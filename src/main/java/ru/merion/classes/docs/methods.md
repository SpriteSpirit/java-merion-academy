# Методы в Java

- блок кода, который выполняет определенные действия или возвращает результат.
- Методы помогают:
    - делить программу на логические части
    - переиспользовать код
    - упростить структуру

```java
// модификаторы, возвращаемый_тип, имя(параметры) { тело }
public int add(int a, int b) {
    return a + b;
}
```

### Аспекты методов:

- объявление метода указывается:
    - имя
    - возвращаемый тип
    - параметры (если есть)
    - тело метода

### Сигнатура метода

- уникальное описание метода, по которому компилятор отличает его от других методов класса.
- в сигнатуру включаются:
    - имя метода
    - список параметров (их типы и порядок)
    - !!! возвращаемый тип и модификаторы в сигнатуру не входят !!!
- если имя разное - это уже другой метод и вопрос про сигнатуру не встает.
- имя одинаковое, параметры разные → перегрузка метода (overloading)

```java
// это две разные сигнатуры, поэтому это перегрузка метода (overloading)
void greet(String name) {...}

void greet(int age) {...}

// это просто 2 разных метода. Это не перегрузка, а значит сигнатуры сравнивать нет смысла.
void greet(String name) {...}

void welcome(String name) {...}
```

### Возвращаемый тип

- метод может ничего не возвращать (void)
- метод может вернуть результат при помощи return (int, float, double, string, etc.)

```java
int square(int x) {
    return x * x;
}
```

### Параметры метода

- передаются в круглых скобках
- могут быть любого типа (включая объекты)
- внутри метода они ведут себя как локальные переменные (копируются по значению - важно для
  примитивов)

### Перегрузка методов (Overloading)

- в классе можно создать несколько методов с одним именем, если у них разные сигнатуры

### Передача аргументов в методы

- всегда передаются по значению
- но:
    - у примитивов передается копия значения
    - у объектов передается копия ссылки на объект

| Тип                                    | Что передаётся                   | Можно изменить оригинал? | Почему                           |
|----------------------------------------|----------------------------------|--------------------------|----------------------------------|
| `int`, `double`                        | Копия значения                   | ❌ Нет                    | Передаётся значение              |
| `Integer`, `String`                    | Копия ссылки на immutable-объект | ❌ Нет                    | Ссылка новая, объект не меняется |
| `Box`, `List`, и др. (mutable-объекты) | Копия ссылки                     | ✅ Да                     | Меняются внутренности объекта    |

```java
// примитив
void change(int x) {
    x = 5; // только копия, оригинал не меняется
}

// ссылочный тип (изменяемый объект)
class Box {

    int value;

    Box(int v) {
        value = v;
    }
}

void change(Box b) {
    b.value = 5; // изменится оригинальный объект
}


// ссылочный тип (immutable объект):
void change(Integer x) {
    x = x * 2; // создаётся новый объект, оригинал не меняется
}

```

> Java копирует значение аргумента.
> Если это примитив — меняется только копия.
> Если это ссылка на объект — можно изменить объект, но не саму ссылку.

### Модификаторы доступа:

- public - доступен везде
- private - доступ только в теле текущего класса
- protected - доступен наследникам и внутри пакета
- default (без модификатора) - доступен только внутри текущего пакета

### static vs instance методы:

#### 1. static

- связан с классом
- вызывается через класс: Class.staticMethod
- доступа к объекту(this) нет
- используется, когда не нужно обращаться к полям класса

#### 2. instance (обычный метод)

- связан с объектом
- вызывается: new Class().instanceMethod()
- есть тоступ к объекту (this)
- используется, когда нужно работать с состоянием объекта

```java
public static void printInfo() {...}      // static

public void showName() {...}              // instance
```

### Переопределение (overriding)

- позволяет в подклассе переписать поведение метода из родительского класса
- @Override используется, чтобы явно показать: «я переопределяю метод»

```java
class Animal {

    public void makeSound() {
        System.out.println("Some sound");
    }
}

class Dog extends Animal {

    @Override
    public void makeSound() {
        System.out.println("Woof");
    }
}

Animal a = new Animal();
Animal b = new Dog();

a.

makeSound(); // "Some sound"
b.

makeSound(); // "Woof" — сработал метод из Dog
```

### Разница между overloading и overriding

| Что          | Overloading                       | Overriding                              |
|--------------|-----------------------------------|-----------------------------------------|
| Где работает | В одном классе                    | В подклассе                             |
| Требование   | Имя одинаковое, параметры разные  | Имя, параметры и тип — такие же         |
| Цель         | Несколько вариантов одного метода | Изменить поведение родительского метода |

| Где применяют `static`?                         | Почему это уместно                                       |
|-------------------------------------------------|----------------------------------------------------------|
| **Утилиты и вспомогательные методы**            | Например: `Math.max()`, `Collections.sort()`             |
| **Главный метод программы**                     | `public static void main(String[] args)` — всегда static |
| **Когда метод не зависит от состояния объекта** | Тогда нет смысла создавать объект ради вызова            |

```java
public class MathUtils {

    public static int square(int x) {
        return x * x;
    }
}

int result = MathUtils.square(5);
```

### Когда лучше не использовать static?

| Не стоит делать `static`, если:                  | Почему это плохо                                  |
|--------------------------------------------------|---------------------------------------------------|
| Метод работает с `this` или полями объекта       | `static` не имеет доступа к данным объекта        |
| Ты хочешь наследовать поведение и переопределять | `static` не поддаётся overriding'у по-нормальному |
| Метод связан с логикой конкретного экземпляра    | Лучше использовать обычный метод                  |

### Главное правило Java:

🔸 Если метод работает с данными конкретного объекта — он должен быть нестатическим.
🔹 Если метод просто делает какую-то общую операцию — он может быть static.

### Фабричный метод (static factory method)

- создает и возвращает объект вместо того, чтобы вызывать new напрямую.
- является "фабрикой по созданию объектов"

```java
public static Dog ofHomeless(String name, Integer age) {
    return new Dog(name, age);
}

Dog dog = new Dog("Шарик", 5); // прямой вызов конструктора
Dog dog = Dog.ofHomeless("Шарик", 5); // вызов фабричного метода

```

> static factory method:
> наглядно говорит, что создаёт «бездомного пса»
> читабельнее: Dog.ofHomeless(...) легче понять, чем new Dog(...)
> можно внутри метода делать дополнительную логику, если нужно

### Когда и зачем использовать static factory method

| Когда использовать                | Почему это удобно                                    |
|-----------------------------------|------------------------------------------------------|
| Нужно **понятное имя создания**   | `ofHomeless`, `ofPuppy`, `fromJson`, `empty()`       |
| Нужно **спрятать `new`**          | Можно внутри метода добавить логику, проверки и т.п. |
| Нужно **контролировать создание** | Например, возвращать кэшированный объект             |

```java
// примеры разных фабрик
public static Dog ofPuppy(String name) {
    return new Dog(name, 0);
}

public static Dog ofHomeless(String name, Integer age) {
    return new Dog(name, age);
}
```
