## Переменные

- примитивы
- объекты

| Тип                 | Объект? | Есть ссылка? | Можно изменить «внутренне»? | Описывается как…         |
|---------------------|---------|--------------|-----------------------------|--------------------------|
| `int`               | ❌ Нет   | ❌ Нет        | ❌ Нет — это просто значение | примитив, **value-type** |
| `String`, `Integer` | ✅ Да    | ✅ Да         | ❌ Нет                       | объект, immutable        |
| `Box`, `ArrayList`  | ✅ Да    | ✅ Да         | ✅ Да                        | объект, mutable          |

### 1. Примитивные типы (primitive types)

- это не объекты
- хранят простое значение
- передаются и хранятся по значению
- не имеют методов, полей, ссылок
- можно перезаписать значение переменной

```java
// примитивы
int,double,boolean,char,long,short,byte,float
```

### 2. Ссылочные типы (reference types)

- это объекты
- хранят ссылку на область в памяти, где лежит объект
- передается копия ссылки (не самого объекта)
- можно менять содержимое объекта, если он mutable

```java
// ссылочные типы
String,Integer,List,Map,массивы,
собственные классы
и т.д .
```

### Изменяемость (mutable)

| Тип объекта           | Мутабельность | Примеры                          | Можно изменить состояние? |
|-----------------------|---------------|----------------------------------|---------------------------|
| **Immutable объекты** | ❌ Нет         | `String`, `Integer`, `LocalDate` | Нет — создаётся новый     |
| **Mutable объекты**   | ✅ Да          | `ArrayList`, `HashMap`, `Box`    | Да — можно менять поля    |

### ⚠️ Часто путают:

> Integer — ссылочный тип, но неизменяемый
> int — не ссылочный вообще, он просто значение
> int можно перезаписать, но ты не можешь изменить его “изнутри”, потому что это не объект
>
> В Java:
> Примитивы — это «кирпичи». Просто лежат в памяти.
> 🔸 Объекты — это «контейнеры», на которые ссылаются.
> 🟡 Изменяемые контейнеры можно ковырять изнутри.
> 🔴 Неизменяемые — только выбрасывать и создавать новые.

# 🧠 Как работают типы в Java, C# и Python

## 🔹 Какие бывают типы?

| Язык   | Что бывает?                                                                                   |
|--------|-----------------------------------------------------------------------------------------------|
| Java   | 🔹 Примитивы (`int`, `double`, и т.д.)<br>🔸 Объекты (`String`, `List`, свои классы)          |
| C#     | 🔹 Примитивы (`int`, `float`, и т.д.)<br>🔸 Объекты<br>🟡 + Есть `struct` (особый value type) |
| Python | 🔸 Только объекты (даже числа — объекты)                                                      |

---

## 📤 Что происходит, когда передаёшь переменную в метод?

| Тип                | Что передаётся в метод | Можно изменить оригинал? |
|--------------------|------------------------|--------------------------|
| Примитив (`int`)   | Копия значения         | ❌ Нет                    |
| Объект (mutable)   | Копия ссылки на объект | ✅ Да (можно менять поля) |
| Объект (immutable) | Копия ссылки на объект | ❌ Нет (создаётся новый)  |

✅ Это одинаково в Java, C# и Python!

---

## 📦 Примеры

### Java

```java
void change(Box box) {
    box.value = 100; // меняет оригинал, потому что объект mutable
}

void change(int x) {
    x = 100; // НЕ меняет оригинал, потому что копия
}
```

```csharp
void Change(Box box) {
    box.Value = 100; // меняется оригинальный объект
}

void Change(int x) {
    x = 100; // оригинал НЕ меняется
}
```

```python
def change(lst):
    lst[0] = 100  # меняется оригинал

def change(x):
    x = 100       # оригинал НЕ меняется
```

| Тип             | Mutable? | Пример                |
|-----------------|----------|-----------------------|
| int, float      | ❌ Нет    | нельзя изменить       |
| String, Integer | ❌ Нет    | создаётся новый       |
| List, dict      | ✅ Да     | можно менять элементы |
| Свой класс      | ✅ Да     | можно менять поля     |

> 📦 Примитив — просто значение
> 📦 Объект — ссылка на коробку с данными
> 🔄 Если коробка mutable — её можно менять
> 🔒 Если коробка immutable — нужно создавать новую

### Когда использовать классы-обертки, а когда примитивы?

> ✔ Если значение всегда обязательно — лучше int
> ❗ Если значение может быть null, или используется в обобщениях — Integer
> Integer в методах — нормально, если нужно null, коллекции, обобщения.

| Если...                               | Используй |
|---------------------------------------|-----------|
| значение **всегда есть**, не `null`   | `int`     |
| значение **может быть `null`**        | `Integer` |
| значение используется в `List`, `Map` | `Integer` |
| тебе **нужна производительность**     | `int`     |
