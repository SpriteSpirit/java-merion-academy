**Аннотации** — это специальные метки/пометки в коде Java, которые добавляют информацию к классам, методам, полям или другим элементам программы.

---

### Простая аналогия:
Как стикер-заметка на документе — сама заметка не меняет содержание документа, но дает дополнительную информацию о нем.

---

### Конкретные факты:

**1. Что это технически:**
- Специальный тип интерфейса в Java
- Начинаются с символа `@`
- Не выполняют код самостоятельно

**2. Что НЕ делают аннотации:**
- Не выполняют код
- Не меняют логику программы напрямую
- Не заменяют собой методы или классы

**3. Как выглядят:**
```java
@Override
public String toString() { return ""; }

@Deprecated(since = "9")
public void oldMethod() { }
```

**4. К чему применяются:**
- Классы: `@Deprecated class OldClass {}`
- Методы: `@Override public void method() {}`
- Поля: `@SuppressWarnings("unused") private int x;`
- Параметры: `void test(@NotNull String param) {}`
- Другие аннотации

**5. Кто использует аннотации:**
- **Компилятор** - проверяет `@Override`, генерирует предупреждения для `@Deprecated`
- **Библиотеки и фреймворки** - JUnit, Spring анализируют аннотации во время выполнения
- **Инструменты разработки** - IDE показывают подсказки для аннотированных элементов

---

### Базовый пример:
```java
// Аннотация @Override - метка для компилятора
class Parent {
    void show() { System.out.println("Parent"); }
}

class Child extends Parent {
    @Override  // ← ЭТО АННОТАЦИЯ
    void show() { System.out.println("Child"); }
}
```

Аннотация `@Override` не выполняет код, а говорит компилятору: "проверь, что этот метод 
действительно переопределяет метод из родительского класса".

**Компилятор проверяет `@Override` следующим образом:**

### Процесс проверки:

1. **Компилятор видит аннотацию `@Override` над методом**
2. **Ищет метод с ТАКИМ ЖЕ именем и параметрами в родительском классе/интерфейсе**
3. **Сравнивает сигнатуры методов:**

```java
class Animal {
    void makeSound() { }          // ← Метод в родителе
}

class Dog extends Animal {
    @Override
    void makeSound() { }          // ✓ Совпадает имя и параметры
    
    @Override
    void makeSound(String volume) { }  // ✗ Ошибка: другой параметр
    
    @Override
    void bark() { }               // ✗ Ошибка: нет такого метода в Animal
}
```

### Что именно проверяет компилятор:

**✓ Совпадение:**
- Имя метода
- Типы параметров (порядок и количество)
- Возвращаемый тип (совместимый)

**✗ Ошибки:**
- Метод с таким именем отсутствует в родителе
- Не совпадают типы параметров
- Несовместимый возвращаемый тип

### Пример с ошибкой:
```java
class Parent {
    void process(String data) { }
}

class Child extends Parent {
    @Override
    void process(int data) { }  // Ошибка компиляции: разные параметры
    // Компилятор: "method does not override a method from supertype"
}
```

### Технически компилятор:
1. **Анализирует дерево наследования**
2. **Сверяет таблицу методов родительского класса**
3. **Если точного совпадения нет - ошибка компиляции**

**Аннотация только указывает КОМПИЛЯТОРУ проверить факт переопределения, но не влияет на код внутри метода.**

## **Встроенные аннотации Java (java.lang)**

### 1. @Override
- **Назначение:** Указывает, что метод переопределяет метод суперкласса
- **Параметры:** Нет
- **Пример:**
```java
class Animal {
    void speak() {}
}
class Dog extends Animal {
    @Override
    void speak() {} // Корректное переопределение
}
```

### 2. @Deprecated
- **Назначение:** Помечает элемент как устаревший
- **Параметры:**
- `since` - String - версия, с которой элемент устарел
- `forRemoval` - boolean - будет ли элемент удален в будущем
- **Пример:**
```java
@Deprecated(since = "9", forRemoval = true)
public void oldMethod() {}
```

### 3. @SuppressWarnings
- **Назначение:** Подавляет предупреждения компилятора
- **Параметры:**
- `value` - String[] - типы предупреждений для подавления
- **Пример:**
```java
@SuppressWarnings({"unchecked", "rawtypes"})
List list = new ArrayList();
```

### 4. @SafeVarargs
- **Назначение:** Гарантирует безопасность операции с varargs параметром
- **Параметры:** Нет
- **Пример:**
```java
@SafeVarargs
public final void process(List<String>... lists) {}
```

### 5. @FunctionalInterface
- **Назначение:** Проверяет, что интерфейс является функциональным
- **Параметры:** Нет
- **Пример:**
```java
@FunctionalInterface
interface Converter {
    int convert(String s);
}
```

### Мета-аннотации (для создания аннотаций)

### 6. @Retention
- **Назначение:** Определяет время жизни аннотации
- **Параметры:**
- `value` - RetentionPolicy - политика сохранения
- **Пример:**
```java
@Retention(RetentionPolicy.RUNTIME)
public @interface MyAnnotation {}
```

### 7. @Target
- **Назначение:** Определяет элементы, к которым применима аннотация
- **Параметры:**
- `value` - ElementType[] - допустимые цели
- **Пример:**
```java
@Target({ElementType.METHOD, ElementType.FIELD})
public @interface MyAnnotation {}
```

### 8. @Documented
- **Назначение:** Указывает, что аннотация должна быть в документации
- **Параметры:** Нет
- **Пример:**
```java
@Documented
public @interface Version {
    String value();
}
```

### 9. @Inherited
- **Назначение:** Позволяет наследование аннотации подклассами
- **Параметры:** Нет
- **Пример:**
```java
@Inherited
public @interface Service {}
```

### 10. @Repeatable
- **Назначение:** Позволяет многократное применение аннотации
- **Параметры:**
- `value` - Class - класс-контейнер
- **Пример:**
```java
@Repeatable(Schedules.class)
public @interface Schedule {
    String time();
}
```

Все параметры строго типизированы. Значения должны быть константами времени компиляции.
