# Абстрактные классы
* Это классы-заготовки, которые:
* Нельзя создать напрямую (new AbstractClass() ❌)
* Содержат и реализованные и НЕреализованные методы
* Для классов с общей логикой, но разной реализацией некоторых методов

#### Пример:
```java
abstract class Animal {

    // Обычный метод - уже реализован
    public void breathe() {
        System.out.println("Дышу...");
    }

    // Абстрактный метод - БЕЗ реализации
    public abstract void makeSound();
}

class Cat extends Animal {

    // ОБЯЗАН реализовать абстрактный метод
    public void makeSound() {
        System.out.println("Мяу!");
    }
}
```

### Ключевые особенности:
* Могут иметь поля, конструкторы, обычные методы
* Могут содержать абстрактные методы (без тела)
* Наследуются через extends (один класс!)
* Сочетают общую логику + обязательство реализовать специфику

### Отличие от интерфейсов:
* Абстрактный класс = "частично готовый класс"
* Интерфейс = "контракт на поведение"
* Идеально для семейств объектов с общей базовой логикой! 

### Интерфейс - "Роль" (что умеет?)
### Абстрактный класс - "Семейство" (кто ты?)

```java
// Утка - это Птица (семейство) + умеет летать и плавать (роли)
class Duck extends Bird implements Flyable, Swimmable {

    public Duck() {
        super("Утка");  // Вызов конструктора Bird
    }

    // ОБЯЗАН реализовать абстрактный метод Bird
    public void eat() {
        System.out.println("Клюёт зерно");
    }

    // ОБЯЗАН реализовать метод Swimmable
    public void swim() {
        System.out.println("Плавает в пруду");
    }

    // Flyable уже реализован по умолчанию
}
```

### Главное отличие:
Абстрактный класс	
"Я - птица" (семейство)
Состояние + поведение
Один на класс

Интерфейс
"Я умею летать" (роль)
Только поведение
Много на класс
Только константы
Проще:

Абстрактный класс = "Ты должен быть птицей, вот базовая логика"

Интерфейс = "Ты должен уметь летать, а КАК - твои проблемы"
