Отлично 👏
Тема **встроенных аннотаций в Java** (таких как `@Override`, `@Deprecated`, `@SuppressWarnings`, `@FunctionalInterface`, `@SafeVarargs`) — прекрасная возможность попрактиковаться не только в синтаксисе, но и в понимании *зачем и где* их применять.

Вот **10 практических заданий** с нарастающей сложностью 💪

---

## 🧩 **1. @Override**

**Задание:**
Создай базовый класс `Animal` с методом `makeSound()`.
Создай подкласс `Dog`, который переопределяет этот метод.
Используй аннотацию `@Override`, чтобы явно указать переопределение.

**Цель:**
Понять, что `@Override` защищает от ошибок при неправильном переопределении (например, опечатка в названии метода).

---

## 🧩 **2. Ошибка без @Override**

**Задание:**
Создай тот же пример, но **не используй `@Override`**.
Сделай ошибку в названии метода (`makeSond()` вместо `makeSound()`) и скомпилируй код.

**Цель:**
Убедись, что без `@Override` ошибка не видна на этапе компиляции.

---

## 🧩 **3. @Deprecated**

**Задание:**
Создай класс `MathUtils` с методом `oldSum(int a, int b)` и отметь его как `@Deprecated`.
Добавь новый метод `sum(int a, int b)` и вызови старый в `main()`.

**Цель:**
Посмотреть, как IDE выдаёт предупреждение при использовании устаревших методов.

---

## 🧩 **4. Свой комментарий к @Deprecated**

**Задание:**
Добавь пояснение:

```java
@Deprecated(since = "2.0", forRemoval = true)
```

и в JavaDoc опиши, какой метод использовать вместо него.

**Цель:**
Научиться использовать параметры аннотации `@Deprecated`.

---

## 🧩 **5. @SuppressWarnings**

**Задание:**
Создай метод, в котором ты используешь «сырую» коллекцию:

```java
List list = new ArrayList();
list.add("Text");
```

Добавь `@SuppressWarnings("unchecked")` и попробуй убрать — посмотри разницу.

**Цель:**
Понять, когда и как безопасно подавлять предупреждения компилятора.

---

## 🧩 **6. Несколько предупреждений**

**Задание:**
В одном методе создай:

* неиспользуемую локальную переменную,
* необобщённую коллекцию.

Подави оба предупреждения одной аннотацией:

```java
@SuppressWarnings({"unused", "rawtypes"})
```

**Цель:**
Научиться указывать массив значений в `@SuppressWarnings`.

---

## 🧩 **7. @FunctionalInterface**

**Задание:**
Создай интерфейс `Converter` с одним методом `convert(T value)`.
Добавь `@FunctionalInterface` и попробуй добавить второй метод — посмотри, что произойдёт.

**Цель:**
Понять, что аннотация гарантирует, что интерфейс остаётся функциональным (один абстрактный метод).

---

## 🧩 **8. @SafeVarargs**

**Задание:**
Создай метод с переменным числом параметров типа `List<T>... lists`:

```java
@SafeVarargs
static <T> void printFirstElements(List<T>... lists) {
    for (List<T> list : lists) {
        System.out.println(list.get(0));
    }
}
```

Вызови его с несколькими `List<Integer>` и `List<String>`.

**Цель:**
Понять, зачем `@SafeVarargs` нужна для подавления варнингов о небезопасных операциях с varargs generic.

---

## 🧩 **9. Совместное использование аннотаций**

**Задание:**
Создай класс, в котором:

* есть устаревший метод `@Deprecated`;
* новый метод переопределяет родительский с `@Override`;
* в одном месте подави предупреждение с `@SuppressWarnings`.

**Цель:**
Попробовать комбинировать встроенные аннотации в одном проекте.

---

## 🧩 **10. Мини-проект: “Legacy API Refactor”**

**Задание:**
Создай два класса:

* `OldApi` с устаревшими методами, помеченными `@Deprecated`
* `NewApi`, который их заменяет.
  Создай класс `Main`, где:
* вызываются оба метода;
* предупреждения подавлены выборочно через `@SuppressWarnings`;
* добавлен функциональный интерфейс `Action` с `@FunctionalInterface`, реализуемый лямбдой.

**Цель:**
Закрепить все встроенные аннотации в одном примере и увидеть, как они помогают документировать, защищать и улучшать код.
